Settings

        
    

    
guided setup with a folder browser

    

    

        A local folder (Z:\Music, /mnt/music), or a network location read directly — no drive mapping needed:
        smb://nas.local/Media/Music for a Windows/Samba share,
        webdavs://cloud.example.com/remote.php/dav/files/myuser/Music (or the plain https:// URL) for WebDAV (Nextcloud, ownCloud, NAS WebDAV servers).
        Never put the password in the URL. 

    

        

        

        

        

        
Saved passwords and keys are never shown again — leave the field blank to keep the saved one. They are stored in config.json (readable only by your user), or can be supplied via the ARTMGR_STORAGE_PASSWORD / ARTMGR_FANART_KEY / ARTMGR_DISCOGS_TOKEN environment variables instead.

create a key

    
Redacted: in your profile settings → Access Settings → API Keys, create a key with only the Torrent scope. Art Manager uses it to find covers and artist images, stays under Redacted's rate limit, and keeps the key on this computer.

    
All optional. iTunes, Deezer, Cover Art Archive, Wikipedia and web search work without any account or key.

Image sources

    

        
CAACover Art Archive — verified scans from MusicBrainz. Often 1500–3000px+. Shown first. Rate-limited, first page only.

        
iTunes3000×3000 supplied directly by labels. Very reliable for major releases.

        
Deezer~1000px album art, good coverage for non-English / obscure releases.

        
DiscogsCommunity high-res scans. Excellent for vinyl, physical releases, non-English music. Discogs only returns images to signed-in API users, so it needs a free personal token (above).

        
WikipediaArtist images — no key needed. Good press photos for known artists.

        
Fanart.tvBest artist photos, typically 1000–1920px. Free API key at fanart.tv.

        
RedactedCovers from Redacted's release groups and artist images, with your own API key (Torrent scope). Shown at the front of the results with CAA.

        
WebGeneral image search via DuckDuckGo and Bing. Neither has an official keyless API — this uses the same unofficial endpoints as their websites, so it may be rate-limited or stop working; it then shows as unavailable and the other sources carry on. Results are filtered for relevance and shown after all other sources.

    

    
CAA and Web load separately (slower): CAA is added to the front of the results, Web to the end. iTunes, Deezer, CAA, Wikipedia and Web need no key.







    

        
Check files

        
    

    
Reads only the start and end of each FLAC file — so it is quick even over the network — and finds
        files that are cut off or damaged, missing tags (title, artist, album, track number), tracks without an embedded cover,
        unreadable or low-resolution cover.jpg files, and albums whose tracks disagree. Files that haven't changed
        since the last check are not read again.
